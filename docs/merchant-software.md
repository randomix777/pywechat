# 商户软件使用说明：从双击到自动接单

本文面向**不懂电脑的商户**。不需要命令行，不需要环境变量，不需要填群名，
不需要 API Key。

---

## 1. 启动

便携版解压后双击“启动微信AI智能助理.bat”；源码开发时可运行
`python -m wechat_ai_assistant.merchant_app`。

```
数据目录：便携版使用 EXE 同级的 `data` 文件夹；源码运行使用 `%LOCALAPPDATA%\wechat-ai-assistant`。旧版便携版首次启动时会把已有 `%LOCALAPPDATA%\wechat-ai-assistant` 或 `%LOCALAPPDATA%\pyweixin` 数据复制到 `data`，原目录保留。
本机名称：DESKTOP-XXXX
本地订单库：已就绪
微信状态：waiting_scan
已登录产品账号：否
待发送回执：0　结果待确认：0
当前模式：后台整理
本地订单查看、人工修改和导出不需要网络。
```

也可以先只做自检，不打开界面：

```powershell
$env:PYTHONPATH = "src"
.\.venv\Scripts\python.exe -m wechat_ai_assistant.merchant_app --check
```

## 2. 第一次使用（六步）

### 第 1 步　检查微信

软件会区分七种状态，每种都有明确的中文提示：

| 状态 | 界面显示 | 您要做的 |
| --- | --- | --- |
| 未安装 | 未检测到电脑版微信 | 先安装 4.0 及以上版本 |
| 未启动 | 微信还没有打开 + **打开微信** 按钮 | 点按钮，然后在微信里登录 |
| 等待扫码 | 请在微信窗口扫码 | 在**微信官方窗口**扫码 |
| 等待手机确认 | 请在手机上确认登录 | 在手机微信点确认 |
| 已登录 | 微信已登录 | 无需操作，自动进入下一步 |
| 离线 | 微信显示网络不可用 | 先恢复网络再点「重新检测」 |
| 无法读取 | 暂时无法读取微信界面 | 退出微信重开；不行就重启电脑 |

**软件不会把微信窗口弹到最前面，也不会动您正在输入的内容。**
被动检测只查询，不移动、不置顶、不激活窗口。���有您点「打开微信」时才会主动启动微信。

已经登录时**不会要求重新扫码**。

### 第 2 步　选择会话

自动列出微信当前能看到的最近会话，支持搜索、刷新。

- 勾选要读历史的会话（可多选）
- 第一版实时接单**只选一个**，在下一步里定

同名会话按群人数区分，例如「鲜果批发群（128人）」和「鲜果批发群（256人）」。
执行前还会再核对一次，核对不上就拒绝操作。

> 这里只列出微信当前能看到的最近会话，**不等于**您的全部联系人和全部历史。
> 想读更早的消息，请先在微信里往上翻一翻再读取。

### 第 3 步　读取历史

选「最近一天」「最近七天」或自定义天数，可填最多读取条数。多会话串行读取，
有进度条，可以随时取消。中途关掉软件，下次启动会从断点继续。

读取历史时软件会短暂操作微信窗口，**请先不要在电脑上做别的事**。

读取完成后会明确告诉您实际读到了什么：

```
您选择的范围是「最近7天」
实际读到 22 条，时间范围 2026-09-25 至 2026-09-27
注意：社区团购 可能还有更早的历史没有读到
```

**不会把固定条数冒充成时间范围。** 撞到条数上限时会如实提示可能不完整。

### 第 4 步　查询分析额度

点「登录产品账号」会在浏览器里打开产品页面，在那里确认「是这台电脑」即可。
界面上**不会显示任何 Key 或地址**。

额度不足时会显示：

```
分析额度已用完
请联系客服开通或续期。（本软件暂不支持在线付款，不会自动扣费）
```

**未接真实支付时明确使用人工开通，不模拟到账。**

额度不足**不会丢数据**：已经读到的消息保留在本地，开通后点「开始智能整理」
即可继续，不会重复读取，也不会重复扣费。

### 第 5 步　智能整理

点「开始智能整理」。结果会显示处理条数、生成订单数、需要核对的条数。
每一单都能追到 `request_id` / `job_id` / `run_id` / `order_id`。

### 第 6 步　开始使用

进入首页。

## 3. 日常使用：首页

首页回答八个问题，不再是「待确认列表」：

| 位置 | 显示 |
| --- | --- |
| 当前状态 | 微信状态、当前会话、当前模式、剩余额度、待发送回执 |
| 右上 | **暂停发送** 按钮 + 是否可发送 |
| 计数 | 今日订单、需要核对、**客户未确认**、**待核对付款** |
| 今日备货汇总 | 按商品聚合总数量、单数、涉及客户 |
| 底部 | 后台整理 / 开启自动接单与回复 / 查看订单 / 云端会发送哪些信息 |

**客户未确认**和**待核对付款**是分开的两个数字。
客户没有回复，只会被记为「客户未确认」，**不会**被标为已确认，更**不会**被标为已付款。
客户声称「钱转了」会进入「待核对付款」，等人工核对收款。

## 4. 两种模式

| 模式 | 记单 | 发回执 |
| --- | --- | --- |
| **后台整理**（默认） | 是 | **否** |
| **自动接单与回复** | 是 | 是（需两道开关） |
| **已暂停** | 视之前状态 | **否**，排队中的回执留着，恢复后继续 |

开启「自动接单与回复」需要两个条件都满足：

1. 模式切到「自动接单与回复」
2. 弹出确认框后**明确同意**「允许这台电脑被自动接单占用」

第 2 条不可省：自动回复要操作微信窗口，可能打断您正在输入的内容。
随时点「暂停发送」立即停止发送。

**未开启第 2 条时，即使选了自动模式也不会发送**，界面会写明
「尚未允许本机自动操作，暂不发送」。

## 5. 自动记单规则

常规订单**不需要**逐单确认。以下条件全部满足才自动记单：

1. 身份明确（由本地系统绑定，模型说出一个名字不算绑定）
2. 商品在您的商品目录里
3. 数量存在、为正、未超上限
4. 单位与目录一致
5. 没有未解决的重复消息候选
6. 改量/追加/取消能唯一关联到一张订单
7. 引用的原文确实出现在消息里
8. 没触发金额、数量或履约异常

**模型自报置信度不作为依据。** 「老样子」找不到对应历史订单时不猜，转异常。

### 各类消息的处理

| 客户说 | 处理 |
| --- | --- |
| 「苹果两箱」 | 新单，自动记单 + 回执 |
| 「老样子，明天送」 | 引用**该客户**的有效历史订单，按当前单价重新核价 |
| 「再加一箱苹果」 | 追加到当前未完成订单 |
| 「改成三箱」 | **改量**，不是追加三箱 |
| 「不要了」 | 取消，必须能唯一关联到一张订单 |
| 「苹果多少钱」 | 询价，**不建单**，也不需要确认 |
| 「钱转了」 | 进入「待核对付款」，**绝不标为已付款** |
| 闲聊 | 不插话 |

### 最多问一个问题

只有关键信息真的缺失时才问，且**最多问一个**。
按人实际会用的顺序找答案：

```
当前消息与引用 → 当前订单 → 该客户有效历史订单 → 您已认可过的默认规则
```

能从历史可靠推断的字段**不再问**。缺少非必要字段不阻止记单。

**缺少本机数据时不问客户** —— 那是系统该知道的，返回给软件补充。

## 6. 自动回复

- 正常订单发送**一次**简洁摘要，并写明「直接回复即可修改」
- 回执按**已校验的订单字段**渲染，模型不参与撰写金额
- **缺价不发零元**：要么显示「价格稍后确认」，要么转异常
- 群回执**不含完整地址和电话**
- 同一客户连续短消息在可配置窗口内合并（默认 45 秒，最多等 90 秒），避免刷屏
- 发送前核对：实际微信账号、会话、订单最新版本、是否暂停
- **不清空您正在输入的草稿**
- 自己的回执**不会**再次触发下单
- 历史导入、重复回放、停机补采**默认不发回执**

### 发送失败怎么办

发送结果不确定时（网络中断、程序崩溃），**不会盲目重发**。
回执进入「结果待确认」，等核对后再决定。避免客户收到两条一样的确认。
