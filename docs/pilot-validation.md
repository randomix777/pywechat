# 受控影子运行验收记录

状态：**未运行**。目前没有获授权的真实商家微信数据、模型服务凭据或商家现场使用记录。只有本地合成数据与软件接口测试通过，三个真实环境关口均不得标记通过。本文件是准备与记录模板，不表示已联系客户或已启动试点。

## 数量口径

- **消息处理动作数**：一条消息触发订单草稿动作、变更动作、人工核对或忽略的次数。同一订单的追加消息仍单独计一条消息动作。
- **订单版本记录数**：保存的草稿、审核建议、已确认版本及历史版本记录；改单/取消可能增加新版本记录，不等同于独立客户订单数。
- **待人工核对订单数**：当前状态为 `review` 或 `cancel_review` 的订单版本数。审核任务关联到订单版本，证据消息可能不止一条。
- **解析失败任务数**：模型解析任务状态为 `failed` 的数目；不会与普通歧义审核混为一类。
- 不将消息数、动作数、审核任务数、版本数相加作为订单数。

## 执行步骤

1. 获得商家与群成员授权后，冻结一段历史消息作为人工标注集；记录商家、账号、群、时区、采集设备、微信版本、导出方法及最早/最晚可见时间。数据脱敏，访问范围限于试点评估人员。
2. 按发送时间切出较早的开发区间和较晚的留出区间。仅用较早的已人工确认订单生成后续记忆；回放某时刻消息时不得检索该时刻之后的订单或人工标签。
3. 先运行 7–14 天只读影子模式，商家人工账本仍是业务真相。系统生成草稿和审核任务，不发送微信群消息、不发货、不扣库存、不记账。
4. 每天执行完整重导、重叠区间重导和至少一次断网/重启恢复演练。导入前后保存范围、message IDs/候选匹配、outbox 数、订单版本变动和人工处置结果。
5. 对每个订单动作记录：日期、匿名客户键、群、消息时间、来源批次、预期意图/客户/SKU/数量/交付日、系统结果、差异类型、审核原因、是否重叠候选、处理人、核对耗时及更正次数。另记解析请求失败、超时、重试与用量；绝不记录 API 密钥。
6. 结束后按以下数字与商家共同复盘：漏单率、错客户率、错 SKU/数量率、重复候选及误报率、确认后重复单数、审核召回率、解析失败可见率、人工核对耗时中位数/P95、更正次数。报告中同时列样本总数与时间覆盖范围。

## 当前去重边界

稳定来源 ID 在商家、群范围内用于精确幂等。来源 ID 较弱时，代码会对不同批次中发送人、解析后发送时刻（±0.5 秒）、正文和消息类型完全吻合的消息建立人工候选，阻止自动建单。该规则刻意不按正文单独合并；人工可确认重复或保留为新消息。

这不是完整的跨批次消息对齐算法：发送时间缺失/精度变化、昵称变化、同名成员、UI 历史切片位移、邻接消息上下文及来源序列错位都需要真实数据验证。无法唯一判定的消息必须保留为缺口或待核对，不能宣称已去重。若候选数量/误报显著影响使用，先改进匹配与人工处置，再进行付费试点。

## 退出/暂停条件

- 商家/群归属错误，租户数据串读，或确认后产生重复单：立即停止该数据流并调查。
- 有消息丢失但导入状态仍显示完整，或模型失败显示为成功：停止影子解析，修复状态显示和恢复路径。
- 人工对照没有达到试点前约定的质量与节时指标：不转入付费试点。
- 真实环境未测的失焦、遮挡、最小化、锁屏、远程桌面断开等监听行为继续保持实验状态；影子历史导入通过不代表后台监听通过。
