状态：**待真实商户、授权数据、人工账本与模型配置**。本文件是准备材料，不代表已联系商户或获得授权。仅开展获授权的离线历史回放；不启动实时监听、不发群消息、不发货、不扣库存、不记账。

## 1. 当前代码入口与已知限制

- **客户初始化**：工作台“客户档案”添加客户，字段为 `name`、群内 `alias`、`group`、可选 `address`。同一群别名若映射多个客户会保留歧义，须由商户提供稳定的匿名客户键并由核对人员人工绑定；不能把昵称当永久 ID。
- **商品初始化**：工作台“商品管理”逐项录入 SKU、名称、别称、单位和当前价格。价格输入为元，服务端保存分为单位；试点前另提供历史价格生效区间，现有商品录入界面没有完整的价格版本/生效期管理，历史订单金额需用账本核对。
- **消息导入**：控制台接受 JSON 数组，必需业务字段为 `sender`、`content`、`sent_at`、`kind`；另可传 `source_id`、`stable_source_id`、`source_confidence`。每条消息独立一行。没有来源稳定 ID 时**不可伪造**稳定 ID；生成的默认 ID 依赖批次和行序，换切片或行序可能产生新身份。
- **时间**：`sent_at` 应含明确 UTC offset，例如 `2026-09-21T09:15:00-04:00`。另存时区、源时间精度和导出方法。不要以导入/采集时间代替发送时间。
- **模型配置**：服务端必须同时配置 `WECHAT_AI_MODEL_BASE_URL`、`WECHAT_AI_MODEL_API_KEY`、`WECHAT_AI_MODEL_NAME`；真实配置通过部署环境的密钥管理/环境变量注入。任一项不全会拒绝启动模型配置；模型失败不会自动切换规则解析。服务商会收到实际解析上下文（消息、客户/商品及符合时间条件的订单记忆），须先批准字段和处理条款。
- **评测入口**：当前入口是控制台导入并解析单批，或业务 API `/api/v1/business/imports` 后调用 `/api/v1/business/parse`。当前没有独立离线回放 CLI、逐条人工账本差异报告或核对耗时采集器；已确认订单 CSV 也不包含所有草稿/审核结果。因此在真实跑数前，逐条结果需从工作台/业务数据导出并人工对齐；不得声称已有自动化评测报告。
- **记忆时序**：模型查询历史订单时使用消息发送时间作为截止，并筛选邻近消息时间；但全量消息可预先导入，未完成订单上下文按当前数据库状态查询。可信评测应隔离数据库，先准备 7 天之前的记忆种子，再严格按时间顺序逐条导入、解析和确认/记录人工裁决，禁止预先导入整段留出期后回放。若无法做到时间递增的隔离回放，则记忆引用结果标记为未验证。
- **弱 ID 判重**：当前只在发送人、精确发送时刻 ±0.5 秒、正文、类型完全匹配时建立候选，并对该消息进入人工判重。裁决记录绑定具体消息 ID 对；相同批次/来源键重放可因消息幂等不再新增，但换批次名/切片而生成新消息 ID 时不会普遍复用旧裁决，可能再次新增判重任务。必须记录每批“新增判重任务数”，并以重叠导入验证复用情况；当前不能宣称已解决重复审核负担。
- **采集来源**：当前工作台 JSON 是手动导入入口；真实微信历史获取仍依赖登录本机和 UI 导出，覆盖范围、稳定 ID、成员标识与真实群完整性均待现场验证。模拟 HTTP 或单元测试不构成实群采集结论。

## 2. 收到样本后的数据包

在商户批准的受限目录存放原件和脱敏评测副本；为两者记录校验和、访问人员与删除日期。聊天正文可能含个人信息。默认不收集无关群、不向模型上传图片/语音原文件；未支持的内容保留类型、时间和待处理标记，不静默删除。需要转写/OCR 时另行取得授权并明确标注。

### 2.1 消息 JSON（转换后的工作台格式）

```json
[
  {
    "sender": "群内原始昵称或经批准的匿名别名",
    "content": "客户原文，不改写",
    "sent_at": "2026-09-21T09:15:00-04:00",
    "kind": "text",
    "source_id": "仅在来源确实提供稳定 ID 时填写",
    "stable_source_id": false,
    "source_confidence": 0.55
  }
]
```

保留原始导出文件，不覆盖源数据。另附批次清单：授权账号匿名键、群 ID/名称、导出工具和版本、导出者、发送时间时区、起止边界、最早/最晚可见消息、行数、无法导出的媒体数、已知缺口和 SHA-256。批次 `source` 应稳定、唯一、描述区间；重叠切片需使用不同批次名以便统计新增判重任务。

### 2.2 客户目录

商户私下保管真实客户身份映射。发给评测系统的表至少包括匿名 `customer_key`、群内别名、别名有效起止、是否人工确认、是否同名歧义。地址仅当本轮配送核对必需且获批准时提供。不要将手机号或无关个人资料作为默认识别字段。

### 2.3 商品目录

字段：`sku`、规范名称、别称、规格、计量单位、换算规则、价格、币种、价格生效起止、人工确认状态。把历史有效价格和当前价格分开，核验“老样子”时按新订单日期查价；禁止把当前价格倒填到历史账本。

### 2.4 人工账本（建议 CSV）

每行一个人工确认的订单动作/版本，建议字段：

```text
event_key,sent_at,group_key,speaker_key,customer_key,intent,target_event_key,sku,quantity,unit,delivery_at,status,ledger_reference,original_manual_minutes
```

对追加、修改、取消填写 `target_event_key`；拆分多商品时按 SKU 多行，但保留同一个 `event_key`。闲聊/询价/付款声称也需纳入消息级标注（可另表），避免只看成交单导致漏单指标失真。付款发言只标“客户声称付款”，不可标成到账。保留核对人、核对时间和账本最后更新时间。

## 3. 离线回放顺序

1. **冻结试点范围**：签收/归档授权、七天消息边界、账本快照、记忆种子区间、目标商家/群及字段上传清单；记下缺失数据和已知微信群不可见边界。
2. **初始化隔离环境**：使用独立业务数据库和商家账号；录入经匿名化的客户别名、商品 SKU/单位/有效价格；绝不复用演示租户或生产商家库。
3. **建立时间种子**：只导入七天开始之前的历史数据。用已确认且账本可核实的历史订单建立记忆；种子消息不计入七天新订单召回指标。对每条种子记录证据与账本来源。
4. **按发送时间回放**：按 `sent_at` 升序；同一时刻按原始稳定顺序，缺少顺序来源则标注歧义。每个事件导入/解析后再处理下一事件。跨日确认策略须固定：评测中的人工答案不得在对应消息解析前写入记忆。
5. **保持原始输出**：每条消息保存解析前状态、订单动作/无动作、客户候选、SKU/数量、目标订单、引用订单、证据、缺失字段、审核原因、解析模式/版本、任务 ID 和错误/重试。无法取到机器可导出的字段时标为“没有采集接口”，不要手工补成系统输出。
6. **人工账本差异对照**：按匿名消息/事件键对齐系统输出和人工标注；人工对照者不知道模型结果时优先独立标注，再复核争议。记录漏单、错客户、错 SKU、错数量/单位、错误追加/改量/取消、错误历史引用、重复单、应审核却生成无歧义草稿、图片/语音未处理、付款误判。
7. **重叠判重试验**：对固定消息范围先导入一次，再以真实导出会产生的新批次名、不同重叠边界重新导入。分别记录新增消息、候选关系、新增 pending 判重任务、已裁决任务数量、旧结论被复用数、误报/漏报、人工处置分钟。至少比较相同批次键重放和新批次名重叠两种情况。
8. **报告后再决定影子运行**：计算样本量和覆盖时间；先与商户约定可接受的错单门槛和人工核对节时门槛。离线回放未通过前，不启动持续影子运行。

## 5. 结束报告最小指标

- 覆盖：授权范围、群、时区、连续天数、消息总数、最早/最晚可见时间、已知缺口、稳定 ID 比例、身份可判比例。
- 业务：订单相关消息召回、错客户率、错 SKU/数量/单位率、错误目标订单/追加改量取消率、重复确认订单数、应审核进入审核比例、引用历史订单正确率、解析失败可见率与重试结果。
- 人工负担：每批新增判重任务数、裁决复用率、误报率、判重人工分钟；原录单和工具核对耗时的中位数/P95及样本数。
- 记忆泄漏：回放排序、每条消息可见的历史截止时间、是否预载未来消息/账本标注；任何无法证明时间隔离的结果标记“不用于准确率结论”。
- 结论标签只能是“真实离线样本通过/未通过/样本不足/待验证”；模拟结果单独列出，不与真实指标混合。
